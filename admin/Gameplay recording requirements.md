# 미니게임 플레이 영상 녹화 기능 — 요구사항 (Claude Code 전달용)

## 목적

인스타 릴스·유튜브 쇼츠용으로 **새 미니게임의 실제 플레이 장면**을 세로 영상(1080×1920, 30fps, mp4)으로 뽑는다.
아직 공개 전(`releaseAt` 이전)인 게임도 미리 녹화할 수 있어야 하고, 같은 명령을 다시 돌리면 같은 결과(같은 당첨자)가 나와야 한다.

대상 게임과 공개일:

| 게임 | 공개일 | 녹화 인원 |
|---|---|---|
| 동물 레이스 | 2026-10-26 (공개됨) | 4명 |
| 숨바꼭질 | 2026-11-02 | 2명 |
| 반응속도 | 2026-11-09 | 4명 |
| 복불복 나눠내기 | 2026-11-16 | 4명, 총액 100,000원 |
| 탑 쌓기 | 2026-11-23 | 4명 |
| 기억력 릴레이 | 2026-11-30 | 4명 |
| 라이어 게임 | 2026-12-07 | 4명 |

데모 참가자 이름: **민수, 지영, 수아, 현우** (숨바꼭질은 민수, 지영). 홍보물과 같은 이름이어야 한다.

## 반드시 지킬 것

- 배포본(`npm run build` 결과, 웹 · 앱인토스 번들 모두)의 동작과 크기는 **바뀌면 안 된다**. 아래 기능은 전부 개발 모드(`import.meta.env.DEV`)나 별도 녹화용 빌드 플래그(예: `VITE_RECORDING=1`)에서만 켜진다.
- 기존 공정성 로직(`crypto.getRandomValues` + 거절 샘플링)은 그대로 둔다. 녹화 모드에서만 난수 공급원을 바꿔 끼운다.
- 먼저 `src/games/registry.js`를 읽고 게임 id, `releaseAt` 처리, 난수 사용 위치를 파악한 뒤 작업한다.

## 1. 녹화 모드 진입 (URL 쿼리, 개발 모드 전용)

| 쿼리 | 동작 |
|---|---|
| `?rec=1` | 녹화 모드 켬 |
| `&unlock=all` | `releaseAt`과 상관없이 모든 게임을 열어 둠 |
| `&players=민수,지영,수아,현우` | 공유 참가자 명단을 이 이름으로 채움 (기존 localStorage 명단은 건드리지 않게 별도 키 사용) |
| `&seed=<문자열>` | 게임 난수를 시드 기반 결정적 난수로 교체 → 같은 시드면 같은 결과 |
| `&game=<id>` | 해당 게임 화면으로 바로 이동 |

녹화 모드에서는 다음을 숨기거나 끈다.

- 광고 자리(AdSense 슬롯), 쿠팡 파트너스 배너
- 효과음 (화면 녹화에는 소리가 필요 없음, 음악은 편집 때 넣음)
- NEW 뱃지와 잠금 표시 (녹화 화면에 "🔒 날짜"가 보이지 않게)

추가하면 좋은 것: 탭한 위치에 반투명 원이 0.3초 보였다가 사라지는 **터치 표시**. 영상에서 어디를 눌렀는지 보이게 하기 위함이다.

## 2. 녹화 스크립트

`scripts/record-gameplay.mjs` (Playwright) 와 `npm run record -- --game=<id>` / `--all`.

- 뷰포트 360×640, `deviceScaleFactor: 3`, 모바일 에뮬레이션(터치 켬), `recordVideo` 크기 1080×1920.
- 개발 서버(`vite`)를 띄우고 `?rec=1&unlock=all&players=…&seed=…&game=<id>`로 연다.
- 게임별 시나리오(아래 3번)대로 탭·드래그를 실제 시간 간격으로 실행한다. 사람이 하는 속도처럼 보이게 동작 사이 간격을 둔다.
- 결과 화면에서 2초 멈춘 뒤, 당첨자가 1명인 게임은 **"정산에 추가"를 눌러 정산 탭에 회차가 생기는 장면까지** 찍는다.
- 결과물:
  - `recordings/<id>.webm` → ffmpeg로 `recordings/<id>.mp4` (H.264, yuv420p, 30fps, 무음 트랙 포함) 변환
  - 핵심 장면 PNG 3~4장 (`recordings/<id>/*.png`) — 시작, 진행 중, 결과
- 3D 게임은 헤드리스에서 WebGL이 안 될 수 있으니 `--use-gl=swiftshader` 또는 headed 모드 옵션을 둔다.

## 3. 게임별 시나리오

각 시나리오는 30초를 넘지 않게 한다(편집에서 잘라 씀). 시드를 바꿔 가며 아래 결과가 나오는 시드를 찾아 스크립트에 고정한다.

| 게임 | 시나리오 | 원하는 결과 |
|---|---|---|
| 동물 레이스 | 4명 배정 → 레이스 15초 전체 | 꼴찌 현우 |
| 숨바꼭질 | 민수·지영이 각자 말 8개 숨기기(빠르게) → 번갈아 찾기, 중간 생략 없이 끝까지 | 지영이 먼저 다 들킴 |
| 반응속도 | 4명 차례로. 민수 0.25초, 지영 0.31초, 수아 0.28초 뒤 터치, 현우는 초록 전에 터치(부정 출발) | 현우 당첨 |
| 복불복 나눠내기 | 총액 100,000원, 4명 → 봉투 차례로 열기 → "정산에 추가" | 가장 많이 내는 사람 공개 후 각자 금액이 든 회차 생성 |
| 탑 쌓기 | 한 사람당 2개씩, 앞 3명은 조금씩 어긋나게 쌓고 현우가 완전히 놓침 | 현우 당첨 |
| 기억력 릴레이 | 앞 3명은 순서를 맞게 누르고 하나 추가, 현우가 틀림 | 현우 당첨 |
| 라이어 게임 | 카테고리 '음식' → 4명이 한 명씩 제시어 확인 → 지목 화면에서 수아를 가장 많이 지목 | 지목된 수아 |

멀티터치가 필요한 손가락 룰렛은 대상에서 뺀다.

## 4. 완료 기준

- `npm run record -- --all` 한 번으로 위 7개 게임의 mp4와 PNG가 생성된다.
- 같은 명령을 다시 돌려도 결과(당첨자, 금액)가 같다.
- `npm run build` 결과물에 녹화 관련 코드가 들어가지 않는다(번들 크기 비교로 확인).
