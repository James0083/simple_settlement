## 공통 규격 (기존 그대로)

- 게임 컴포넌트 `({ players: [{id,name}], onFinish(loserId | loserIds[]), onTie? })` — `GamesScreen.js` 가 참가자 선택 · 결과 · 한 판 더 · 정산에 추가를 맡는다.
- 차례 넘기기: `TurnOrderSetup` · `TurnStrip`(`TurnOrder.js`), `TurnBanner` · `BigButton` · `GAME_FINISH_MS`(`common.js`).
- 난수: `randInt` · `shuffle`(`random.js`). 결과는 가능한 한 시작 때 정한다(탑 쌓기 · 반응속도처럼 실력 게임은 예외).
- 소리 · 진동: `sfx.js`(`beep` · `chime` · `fanfare` · `vibrate` …). `prefersReducedMotion()` 이면 애니메이션을 줄인다.
- 등록: `registry.js` 한 줄 + `gameIcons.js` 아이콘. 문서: `guide/games.html` · `guide.html` 표 · `APP_INFO.md` · `README.md` · `release-notes.html` · `sitemap.xml` lastmod.

## 1. 반응속도 (신호등) 🚦 — `reaction` · 11/9

- **인원:** 2~15명 · **한 판:** 1인 10초 안팎 · **작업량:** 작음

### 규칙
1. 순서를 정하고(`TurnOrderSetup`) 폰을 차례로 넘긴다.
2. "준비됐어요" → 화면이 **빨강**("기다려요…") → 1.5~5초 뒤(무작위, 시작 때 정함) **초록**("지금!").
3. 초록이 된 순간부터 누를 때까지의 시간(ms)을 잰다. 한 사람당 1번.
4. 가장 느린 사람이 당첨.
5. **부정 출발:** 초록 전에 누르면 그 사람은 기록 없이 실격(= 가장 느린 것으로 친다). 실격자가 2명 이상이면 `onTie(실격자들)` 로 재대결. 기록이 1ms 단위까지 같으면 역시 `onTie`.

### 구현
- `pointerdown` 으로 판정(`click` 은 손을 뗄 때라 늦다). `performance.now()` 로 잰다 — 10초 맞추기와 같은 방식.
- 초록이 되는 순간 `beep` + 화면 전체 색 전환. 큰 터치 영역(화면 전체 버튼).
- 결과 목록: 이름 · `0.283초` · 부정 출발 표시.

### 확인할 점
- 기기 · 브라우저마다 화면 반영 지연이 있지만 같은 폰을 돌려 쓰므로 공정하다.
- 초록 직후 50ms 안의 입력은 사람이 낼 수 없는 속도 → 부정 출발로 친다(미리 누르고 있다가 걸린 경우).

## 2. 복불복 나눠내기 🧧 — `splitluck` · 11/16 · **딱정산만의 게임**

- **인원:** 2~15명 · **작업량:** 중간 (게임 규격 확장 포함)

### 규칙
1. 총액을 입력(예: 60,000원). 비워 두면 "비율"로만 보여 준다.
2. 봉투가 인원 수만큼 놓인다. 차례대로 하나씩 열면 그 사람이 낼 금액이 나온다.
3. 다 열면 순위표(많이 내는 순) — 가장 많이 내는 사람을 결과 화면의 "당첨"으로 강조.
4. **정산에 추가** → 회차 하나가 생기고, `customAmounts` 에 각자 금액이 채워진다(공통 금액 0원). 결제자는 비워 둬서 정산 탭에서 고른다.

### 금액 정하기 (시작 때 확정)
- 각자 무게 `w = 0.3 + random()` (최소 부담을 보장해 0원이 안 나오게) → 비율 = w / Σw.
- 금액 = 총액 × 비율을 **100원 단위**로 내리고, 남은 금액은 최대 나머지법으로 100원씩(마지막 끝전은 1원 단위) 나눠 합이 총액과 정확히 같게.
- 단위 테스트: 합 = 총액, 모두 0원 초과, 100원 단위(끝전 1명 제외), 2명 · 15명 경계.

### 규격 확장
- 지금 `onFinish` 는 당첨자 id 만 받는다. 이 게임은 `onFinish(loserId, { amounts: { [id]: 금액 }, total })` 처럼 **두 번째 인자**를 추가한다(기존 게임은 영향 없음).
- `GamesScreen.addToSettle` 이 `extra.amounts` 가 있으면 `s.addRoundFrom({ title, amount: total, participantIds, customAmounts: amounts })` 를 부른다 — `addRoundFrom` 에 `customAmounts` 인자 추가(`makeRound` 기본값 `{}` 위에 덮기).
- `GameResult` 에 금액표(이름 · 금액) 한 줄 추가. 결과 문구 "오늘 제일 많이 내는 사람은 ○○님!".

### 확인할 점
- 총액을 비운 경우 정산에 추가하면 비율만 있고 금액이 없음 → 이때는 기존처럼 결제자 = 당첨자 회차로 넘기거나, 버튼 문구를 "총액을 넣으면 금액까지 넘겨요"로 안내. → **총액 입력을 필수로** 하는 쪽이 단순하다(추천).
- 정산 탭 "금액 따로 입력" 패널이 펼쳐진 상태로 열려야 넘겨받은 금액이 보인다.

## 3. 탑 쌓기 🧱 — `stack` · 11/23

- **인원:** 2~15명 · **작업량:** 중간

### 규칙
1. 바닥 블록 위로 새 블록이 좌우로 왕복한다. 화면을 누르면 떨어진다.
2. 아래 블록과 겹친 부분만 남고 삐져나온 부분은 잘려 떨어진다 → 탑이 점점 좁아진다.
3. 한 사람이 **2개씩** 쌓고 폰을 넘긴다(한 개는 너무 짧다). 같은 탑을 계속 이어 쌓는다.
4. 완전히 빗나가(겹침 0) 블록을 놓친 사람이 당첨. 거의 딱 맞으면(±3%) "퍼펙트"로 폭을 조금 되돌려 준다.
5. 층이 올라갈수록 왕복 속도가 빨라진다(상한까지). 탑이 계속 좁아지고 빨라지므로 따로 끝 조건을 두지 않아도 누군가는 놓친다.

### 구현
- SVG 또는 `<canvas>` 2D(Three.js 불필요). `requestAnimationFrame` 으로 위치 계산, 탑이 높아지면 화면을 아래로 내려 위쪽 6~8층만 보인다.
- 잘린 조각 떨어지는 연출 · `tapPop` 소리 · 놓치면 `explosion` + 진동.
- 판정은 순수 함수 `overlap(prev, cur)` 로 빼서 단위 테스트.

## 4. 기억력 릴레이 🎵 — `simon` · 11/30

- **인원:** 2~15명 · **작업량:** 작음~중간

### 규칙
1. 색 버튼 4개(2×2). 첫 사람이 아무 버튼 하나를 누르고 넘긴다.
2. 다음 사람은 **지금까지의 순서를 그대로** 누른 뒤 자기 것을 하나 더한다.
3. 틀리게 누르면 그 사람 당첨 → 정답 순서를 다시 보여 준다.
4. (선택) 시작할 때 "보여주기 모드": 차례가 넘어갈 때 앞 순서를 한 번 재생해 주는 쉬운 모드 / 안 보여주는 어려운 모드. 기본은 **어려운 모드**(술자리용).

### 구현
- 버튼마다 고정 음(`beep(도·미·솔·도')`) + 눌림 빛. 같은 사람이 이어 누를 때 연타 방지 150ms.
- 입력 중 "3 / 7" 진행 표시.
- 판정 로직(`checkInput(seq, inputs)`)을 순수 함수로 빼서 단위 테스트.

## 5. 라이어 게임 🤥 — `liar` · 12/7

- **인원:** **3~10명** · **작업량:** 중간 (제시어 데이터 포함)

### 규칙
1. 카테고리 고르기(음식 · 장소 · 직업 · 동물 · 영화 장르 …).
2. 폰을 돌려 가며 "준비됐어요" → 제시어 확인 → "확인했어요". 라이어 1명은 "당신은 라이어예요"만 본다. (`UpDownGame` 의 비공개 입력 패턴)
3. 앱이 시작 순서를 무작위로 정해 보여 주고, 각자 말로 한 문장씩 설명(앱은 타이머만, 선택).
4. 투표 화면: 폰을 돌려 가며 한 명씩 지목(자기 자신 제외) — 또는 다 같이 말로 정하고 한 번에 고르는 "빠른 투표".
5. 판정:
   - 최다 득표 = 라이어 → **라이어 당첨**.
   - 최다 득표 ≠ 라이어 → **최다 득표자 당첨**(엉뚱한 사람으로 몰린 벌).
   - 원작의 "잡힌 라이어가 제시어를 맞히면 역전"은 넣지 않는다 — 역전 시 누가 낼지 애매하고, 판정이 단순해야 정산으로 넘기기 쉽다.
   - 최다 득표 동점 → `onTie(동점자)` 대신 결선 투표 한 번 더.

### 구현
- 레지스트리에 **`minPlayers`** 필드 추가(`exactPlayers` 와 같은 자리): `playersOkFor` 가 `game.minPlayers ?? MIN_PLAYERS` 를 쓰고, 안내 문구 "라이어 게임은 3명 이상이 필요해요".
- 제시어: `src/games/liarWords.js` — 카테고리당 30~50개. 음식은 뭐먹지 메뉴 목록에서 가져와 재사용.
- 결과 화면에 라이어 · 제시어 공개.

### 확인할 점
- 제시어 목록은 정치 · 특정 인물 · 비속어 제외(앱인토스 검수).
- 시간이 길어지는 게임이라 카드 설명에 "약 5~10분"을 적는다(숫자 맞추기와 같은 방식).

## 순서와 이유

1. **반응속도** 먼저 — 작업이 작고 모든 인원에서 바로 재미있다. 숨바꼭질(2인 전용) 다음 주에 다시 "누구나" 게임.
2. **복불복 나눠내기** — 차별점이 가장 크지만 규격 확장이 있어 한 주 여유를 둔다.
3. **탑 쌓기 · 기억력** — 서로 독립적이라 순서를 바꿔도 된다.
4. **라이어** 마지막 — 제시어 데이터 준비 시간이 필요하고 `minPlayers` 추가가 따라온다. 연말 모임 시즌(12월)과 맞는다.
