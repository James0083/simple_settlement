## 1. 원칙

1. **정산이 먼저.** 딱정산은 돈 계산 도구라 신뢰가 핵심이다. 입력 중·계산 중에는 광고를 두지 않고, 할 일을 끝낸 뒤(결과 아래)에만 둔다.
2. **게임 중에는 광고 없음.** 폰을 돌려가며 누르는 게임(폭탄 넘기기 버튼, 3D 탭)이라 잘못 누르기 쉽다. 애드센스도 게임 조작부 근처 배치를 금지하고 최소 150px 간격을 권장한다.
3. **팝업은 "자연스러운 쉼표"에서만.** 화면을 여는 순간 뜨는 팝업·전면광고는 Better Ads Standards 위반이다. 위반하면 Chrome이 사이트 전체 광고를 차단할 수 있다.
4. **결과 이미지에 광고 금지.** 정산 결과 이미지(`captureRef`)와 공유용 텍스트에는 광고가 들어가지 않게 한다. 지금 광고 자리도 캡처 영역 밖에 있다.

## 2. 위치 검토

### 배너 (현재 확보된 4곳)

| 순위 | 자리 (`placement`) | 위치 | 크기 | 판단 | 이유 |
|---|---|---|---|---|---|
| 1 | `food-result` | 뭐먹지 추천 결과 아래 (다시 뽑기·정산 추가 버튼 아래) | 320×100 | **추천** | 먹을 것을 고르는 순간이라 음식·배달 광고와 맞아 클릭 가치가 높다. 결과를 본 뒤 자연스럽게 스크롤이 끝나는 곳이다 |
| 2 | `game-result` | 미니게임 결과 아래 (한 판 더·다른 게임 버튼 아래) | 320×100 | **추천 (조건부)** | 결과를 보는 순간 여러 명이 화면을 본다. 다만 "한 판 더" 버튼 바로 아래라 잘못 누를 위험이 있어 **간격 32px 이상 + "광고" 표기**가 필요하다(지금은 16px) |
| 3 | `settle-result` | 정산 결과(복사·이미지 저장 버튼) 아래 | 320×100 | **보통** | 결과를 복사하느라 머무르는 시간은 길지만, 곧바로 앱을 떠난다. 버튼과 간격을 충분히 두면 괜찮다 |
| 4 | `games-list` | 미니게임 카드 목록 아래 | 320×50 | **낮음** | 대부분 게임 카드를 바로 눌러 들어가 노출이 적다. 트래픽을 보고 뺄지 정한다 |

**두지 않을 곳**

| 위치 | 이유 |
|---|---|
| 정산 입력 영역(참가자·회차 사이) | 입력을 방해한다. 입력칸 옆 광고는 잘못 누르기 쉽다 |
| 게임 플레이 화면(순서 정하기 ~ 결과 전) | 조작부 근처는 정책 위반 위험. 3D 캔버스·넘기기 버튼과 가깝다 |
| 뭐먹지 "메뉴 정하기" 버튼과 결과 사이 | 결과보다 광고가 먼저 보여 불쾌하고, 버튼 근처라 잘못 누르기 쉽다 |
| 하단 탭바 위 고정 배너(앵커) | 탭바·게임 버튼과 겹친다. 320×50은 허용 범위지만 화면이 좁아진다. 트래픽이 충분할 때 목록 화면에서만 따로 검토한다 |

| 형식 | 언제 | 판단 |

## 3. 게재 조건

### 3-1. 배너 광고 조건

- **표시**
  - 광고 위에 작은 **"광고"** 라벨을 단다. 광고임을 알아볼 수 있어야 한다(표시광고법, 애드센스 라벨 정책).
  - 버튼·링크와 **위아래 32px 이상** 띄운다.
- **밀도**
  - 한 화면(스크롤 전체 기준)의 광고 높이 합이 **본문 높이의 30% 이하**여야 한다(Better Ads 모바일 기준).
  - 지금 배치는 화면당 1개라 여유가 있다.
- **노출하지 않는 경우**
  - 광고 제거 구매자(`isAdFree()`)
  - 오프라인
  - 광고를 불러오지 못했을 때: 빈 칸 없이 접는다. 자리를 미리 비워 두지 않아 화면이 밀리지 않게 한다.
- **움직임**
  - 자동 재생 소리, 번쩍이는 애니메이션, 화면 30%를 넘는 고정(sticky) 광고는 쓰지 않는다.

### 3-2. 전면광고(팝업형) 조건

| 항목 | 조건 |
|---|---|
| 뜨는 시점 | 미니게임 결과 후 "한 판 더" · "다른 게임"을 누른 직후만 |
| 첫 판 | 방문 후 **첫 결과에는 띄우지 않음** (처음 쓰는 사람을 보호) |
| 빈도 | **3판마다 최대 1회**, 그리고 직전 전면광고 후 **3분 이상** 지나야 함 |
| 닫기 | 처음부터 닫기 버튼이 보여야 함 — **카운트다운 후에야 닫히는 방식 금지**(Better Ads 위반) |
| 안 띄우는 곳 | 정산 탭, 뭐먹지 탭, 게임 진행 중, 소리·진동이 나는 순간 |
| 준비 안 됨 | 광고가 준비되지 않았으면 기다리지 않고 바로 다음 화면으로 (로딩 스피너 금지) |
| 소리 | 전면광고가 떠 있는 동안 게임 효과음·배경음을 멈추고, 닫으면 복구 |
| 구현 | 애드센스 **H5 Games Ad Placement API** 의 `adBreak({ type: "next" })` — 빈도 조절 기능이 들어 있다 |

### 3-3. 보상형광고 조건

- 사용자가 버튼을 눌러 **직접 선택**할 때만 보여준다. 자동으로 띄우지 않는다.
- 끝까지 봤을 때만 보상(유료 게임 1판)을 주고, 보상 내용을 버튼에 미리 적는다("광고 보고 1판 무료").
- 보상은 그 기기, 그 판에만 준다. 저장이 필요하면 `ddak:entitlements` 에 기한을 붙인다.

### 3-6. 광고 네트워크 선택

| 네트워크 | 장점 | 단점 | 추천 용도 |
|---|---|---|---|
| **구글 애드센스** | 배너 + **게임 전면·보상형(H5 Games Ads)** 을 모두 지원한다. 광고 수요가 많다 | 도메인·ads.txt·CMP 준비가 필요하다. 승인이 까다롭다 | 게임 전면·보상형 + 배너 |
| **카카오 애드핏** | 국내 광고, 한국어 소재가 잘 맞는다. 심사가 영업일 1~2일로 빠르다. 개인도 본인 인증 후 가입할 수 있다(만 14세 이상) | 웹에서는 배너 위주. 사행성·리워드 콘텐츠 제한(3-5). 다른 네트워크와 같은 화면에 섞을 수 없다 | 뭐먹지 · 정산 결과 배너 |
| 앱 스토어 배포 시 (TWA/Capacitor) | 애드몹(AdMob) 전면·보상형 | 앱으로 포장해야 한다 | 나중에 |

**제안하는 순서**
1. 전용 도메인을 연결한다.
2. 개인정보처리방침과 서비스 워커를 고친다.
3. **카카오 애드핏 배너 2곳**(`food-result`, `settle-result`)으로 시작한다. 게임 화면은 사행성 오해를 피하려고 뺀다(3-5).
4. 트래픽이 쌓이면 애드센스를 신청하고, 게임 화면에 **배너(`game-result`) · 전면광고 · 보상형 "유료 게임 1판 체험"** 을 추가한다. 이때 게임 화면에는 애드핏을 두지 않는다.
5. 광고 제거 구매(`isAdFree`)를 연다.

## 4. 코드에서 광고를 켤 때 할 일

1. `src/components/AdSlot.js`
   - `AD_ENABLED = true` 로 바꾸고, 네트워크 코드(애드핏 `<ins class="kakao_ad_area">` 또는 애드센스 `<ins class="adsbygoogle">`)를 넣는다.
   - "광고" 라벨을 달고, 광고를 불러오지 못하면 자리를 접는다.
2. `GameResult.js`: 광고 자리 위 간격을 16px → 32px 이상으로 늘린다.
3. `sw.js`: 광고 도메인(예: `*.kakao.com/adfit`, `pagead2.googlesyndication.com`, `*.doubleclick.net`)은 `fetch` 에서 가로채지 않도록 예외를 둔다.
4. 전면광고
   - `GamesScreen.js` 의 `again()`, "다른 게임" 링크에서 빈도 조건을 확인하고 `adBreak` 를 부른다.
   - 광고가 떠 있는 동안은 `setSoundOn` 이 아니라 마스터 볼륨만 잠시 내린다.
5. 보상형
   - 잠긴 게임 카드의 `openGame` 에서 "광고 보고 1판" 선택지를 띄운다.
   - 보상을 받으면 그 판만 `canPlay` 를 허용한다.
6. `privacy.html` 3번 항목과 `terms.html` 을 고친다.
7. 캐시 버전(`CACHE`)을 올린다.

## 6. 광고를 허용하는 무료 호스팅 · 앱으로 배포하기 (2026-09-29 조사)

### 6-1. 무료 호스팅 비교
공통 조건: **어느 곳이든 무료 주소(`*.pages.dev`, `*.netlify.app`, `*.github.io`)로는 애드센스 승인이 안 된다.** 애드센스는 최상위 도메인 소유자를 기준으로 승인하기 때문이다. 전용 도메인은 어디서든 필요하다(연 1~2만 원대).

| 호스팅 | 무료 플랜 상업적 사용 | 광고 | 무료 한도 | 판단 |
|---|---|---|---|---|
| **Cloudflare Pages** | ✅ 허용 | ✅ 제한 없음 | 대역폭 무제한, 빌드 월 500회, 파일 2만 개 | **1순위.** 대역폭 초과 걱정이 없다 |
| **Netlify (Free)** | ✅ 허용 (호스팅 재판매만 금지) | ✅ | 대역폭 월 100GB 등. **넘으면 그달 남은 기간 사이트 정지** | 2순위. 방문자가 많아지면 정지될 수 있다 |
| **GitHub Pages** | △ "온라인 사업·SaaS용 무료 호스팅"은 금지. 개인 프로젝트에 붙는 일반 광고는 허용되는 것으로 안내됨 | △ | 대역폭 월 100GB(권장치) | 가능하지만 약관 해석 여지가 있어 비추천 |
| Vercel (Hobby) | ❌ 금지 | ❌ | — | 광고를 붙이려면 Pro(유료) 필요 |

→ **Cloudflare Pages + 전용 도메인**이 가장 무난하다. 이 앱은 빌드가 없는 정적 파일이라 폴더를 그대로 올리면 되고, 도메인도 Cloudflare에서 원가로 살 수 있다.

### 6-2. 앱으로 만들어 스토어에 올리면 광고를 붙일 수 있나?

| 방식 | 설명 | 애드센스 | 애드핏 | 애드몹(앱 전용 광고) |
|---|---|---|---|---|
| **① TWA (안드로이드 전용)** — Bubblewrap/PWABuilder로 지금 사이트를 감싸 Play 스토어에 올림 | 앱 안에서 실제 크롬이 사이트를 그대로 띄운다. 코드 수정 거의 없음 | ✅ 웹사이트 광고가 그대로 나온다(사이트 기준 승인) | ✅ 웹 스크립트 그대로 | ❌ 못 씀 |
| **② 웹뷰 앱** — Capacitor 등으로 사이트를 앱 안에 포함 | 앱이 웹 화면을 품는 방식 | △ 구글 "WebView API for Ads" 등록 필요. 사이트 승인 별도 | △ 애드핏은 "하이브리드 앱은 원칙적으로 기술 지원 안 함" | ✅ 플러그인으로 배너·전면·보상형 가능 |
| ③ 네이티브 앱 새로 개발 | 전부 다시 만듦 | — | ✅ 애드핏 안드로이드/iOS SDK | ✅ |

**비용·심사**
- Google Play 개발자 등록: **1회 25달러.** 새 개인 계정은 출시 전 **테스터 12명이 14일 동안 비공개 테스트**를 해야 한다.
- Apple App Store: **연 99달러.** 사이트를 감싸기만 한 앱은 **가이드라인 4.2(최소 기능)로 거의 반려된다.** iOS 출시는 현실적으로 어렵다.
- TWA도 도메인 소유를 증명해야 한다(`/.well-known/assetlinks.json`). **결국 전용 도메인이 필요하다.**

**결론**
- 앱으로 만든다고 광고 조건이 쉬워지지 않는다. 애드센스·애드핏은 여전히 **"전용 도메인의 웹사이트"로 승인**받아야 한다.
- 가장 가벼운 길: **Cloudflare Pages + 도메인 → 웹에서 애드핏/애드센스 승인 → (원하면) TWA로 Play 스토어 출시.** 같은 광고가 앱에서도 나온다.
- 애드몹(앱 광고, 전면·보상형이 강함)을 쓰려면 ② Capacitor 방식이 필요하다. 안드로이드 스튜디오 빌드, 앱 안 광고 처리 코드가 추가돼 작업량이 크다. 방문자가 생긴 뒤 검토한다.
